# TurboJev — Python

Uses **turbojev 0.34.0 from PyPI**, not local SDK source. Install with the same Python interpreter you use to run the demo.

```powershell
python -m pip install -r requirements.txt
python main.py ticket
python main.py fields
python main.py fair-die --device gpu
python main.py receipt --device gpu --fields first_item,total
python main.py receipt-us --image C:/photos/receipt.jpg --device gpu
```

`ticket` calls `evaluate`; `fields` calls `generate` and demonstrates integers, decimal numbers, boolean probabilities, actual null, dependencies and conditional omission. All modes are implemented in this folder's `main.py`. Downloads, reporting, request schemas and receipt assets are included here. You can copy this folder elsewhere and run it without the other demos or any parent Python files.

CPU is the default. GPU is explicit and does not fall back. Text uses QJev3.5 0.8B v19c GGUF; image extraction uses Qwen3.5 2B plus a matching projector. Download progress, transfer speed and ETA appear on first use; all languages reuse `~/.cache/turbojev` where compatible. `--model PATH` selects a local GGUF; receipts also accept `--mmproj PATH`. `--fields` selects a recorded subset including dependencies. See `python main.py <example> --help` for each mode's options.

Receipt answers and dependent arithmetic are generated by the model, with expected labels checked only afterward. Full image runs can take minutes and small models can make mistakes. Each receipt field repeats inference and image preprocessing. `--max-tokens` bounds text/numeric output per field (default 64). Receipt requests disable thinking because that runtime mode is unsupported. The CORD photo is bundled; the US photo is not redistributed, so `receipt-us` requires `--image`. Custom photos are not compared with reference labels unless you select `--reference-labels` for the exact reference image.

Fair die compares permutation budgets `1`, `auto` and `8`. `--all-permutations` adds all **720** layouts and can be very slow. The uniform reference distribution is used only to measure model outputs; no answer is substituted by the host.

Reports for ticket/fields default to `result-<example>.json` in the working directory. Fair die and receipts default to `result-fair-die.json`, `result-receipt.json` and `result-receipt-us.json` in this folder. `--output PATH` overrides the destination.

## Structured SDK examples (TurboJev 0.34.0)

```sh
python main.py structured
python main.py hierarchical
python main.py discover-categories
python main.py dice
python main.py limits
```

All use the registry package, never a workspace build. Dice samples from the
model distribution with seed 42; fair-die measures the distribution with greedy
decoding and compares it with 1/6 per face. Auto costs six layouts, and all costs 720. Numeric limits constrain generated digits, including fractional digits.

QJev is specialized in bounded decisions. For open text/number extraction,
arrays or model reasoning, select a general instruction GGUF with `--model PATH`
(or `TURBOJEV_MODEL`). The example schemas stay unchanged; the host never
fabricates an answer. QJev is not expected to reproduce those generation demos.
Its upstream accuracy/calibration figures use a different prompt/scoring path
and do not describe these TurboJev runs. Alternative model URLs and integration
requirements are commented next to the model configuration in each entry point.
